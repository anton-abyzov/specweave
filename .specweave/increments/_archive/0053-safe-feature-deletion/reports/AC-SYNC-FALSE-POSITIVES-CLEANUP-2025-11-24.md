## Summary

Cleaned up 140 false positive AC sync conflicts from metadata.json that were generated by the buggy AC parser (pre-v0.25.2).

**Pattern**:
```
AC-US1-01: [x] but only 0/1 tasks complete (0%)
AC-US1-02: [x] but only 0/1 tasks complete (0%)
...
(70 ACs × 2 duplicates = 140 total conflicts)
```

**Why False Positives?**

1. **All conflicts showed "0% tasks complete"** - signature of parser bug
2. **tasks.md showed 37/37 completed** - reality was 100% done
3. **Increment successfully closed** at 07:23 UTC - validation passed
4. **Parser bug documented** in CLAUDE.md section 7b

## The Bug

**Problem**: AC sync parser (pre-v0.25.2) only detected list format checkboxes (`- [x]`), completely missing field format (`**Status**: [x] completed`) introduced in v0.23.0.

**Impact**: All 70 ACs in increment 0053 showed false "0% tasks complete" even though tasks.md clearly showed 37/37 tasks with `**Status**: [x] completed`.

## The Fix

**Version**: v0.25.2
**File**: `src/core/increment/ac-status-manager.ts:150-156`

```typescript
// Check for field format: **Status**: [x] completed
else if (line.match(/\*\*Status\*\*:\s*\[x\]/i)) {
  hasCheckedBoxes = true;
}
// Check for field format: **Status**: [ ] pending
else if (line.match(/\*\*Status\*\*:\s*\[\s\]/i)) {
  hasUncheckedBoxes = true;
}
```
