## Recommendations

### 1. Add Missing Hook #13 to Contributors
```bash
# In install-git-hooks.sh, after check #12, add:

# 13. Check for root folder pollution (CRITICAL - prevents workflow breakage)
if [ -f "scripts/pre-commit-root-pollution-check.sh" ]; then
  if ! bash scripts/pre-commit-root-pollution-check.sh; then
    exit 1
  fi
fi
```

### 2. Create User Hook Template

**Location**: `src/templates/git-hooks/pre-commit.template`

**Checks for Users (in order)**:
1. **Root pollution check** (CRITICAL) - Blocks .md files in project root
2. **Increment folder cleanliness** - Blocks files outside reports/scripts/logs
3. **Duplicate increment detection** - Prevents data corruption
4. **YAML frontmatter validation** - Prevents malformed spec.md
5. **Status desync detection** - Keeps tasks.md and metadata.json aligned
6. **Mass .specweave/ deletion** (>50 files) - Test cleanup protection

### 3. User Hook Installation Paths

**Path A: During `specweave init`**
```
? Install git hooks for quality enforcement? (Y/n)
  ✓ Root pollution check (blocks .md files in project root)
  ✓ Increment validation (prevents data corruption)
  ✓ YAML validation (prevents malformed spec.md)
```

**Path B: After init via CLI**
```bash
specweave install-hooks
# or
specweave hooks install
```

**Path C: Manual (documented)**
```bash
# Copy pre-commit hook
cp .specweave/templates/git-hooks/pre-commit .git/hooks/
chmod +x .git/hooks/pre-commit
```

### 4. Simplified User Hook Scripts

**Don't copy all framework scripts!** Create simplified, self-contained checks:

**Option A: Single monolithic pre-commit** (simpler)
- All logic in one file
- No dependencies on external scripts
- ~300 lines total

**Option B: Modular with check scripts** (better maintainability)
- Main pre-commit orchestrator
- Individual check scripts in `.specweave/hooks/`
- Can enable/disable specific checks via config

**RECOMMENDED: Option A** for users (less complexity, easier to understand)
