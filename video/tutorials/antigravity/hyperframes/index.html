Run one small change with Antigravity and Gemini in spec
with code. This walkthrough prepares the task. It does not
submit a provider run.
In Settings, Providers, enable antigravity on the project's
machine, install its runtime, and complete its separate sign
-in. Wait for account access and the model list. Choose a
Gemini model that account actually offers.
Open an example repository as a project. The main
conversation is the project coordinator. Check which machine
is doing the work.
Select Antigravity, then an available Gemini model and the
approval mode you intend to use. This tutorial does not
require full access.
Give it one bounded task. Add a named greeting, keep the no
argument greeting working, and add tests for both. Ask it to
describe the change before editing. Antigravity has its own
native plan command. Do not assume the app's separate plan
mode is available.
Read the proposed change, then ask it to implement. Review
any command approval rather than accepting it automatically.
Inspect the changed files and the actual test output. If a
check failed or was not run, keep that in the result. A
confident reply is not test evidence.
Finish with the change, its diff, and actual test evidence.
Use specweave increments when you need a durable plan and
task record. They are optional for this first task.
