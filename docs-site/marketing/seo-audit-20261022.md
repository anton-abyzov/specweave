# SpecWithCode is discoverable, but the spaced brand lacks a clear signal

Search results do contain SpecWithCode's product page, documentation, tutorials and Chrome extension. The user's Google screenshot shows a real discovery problem for **spec with code**, but it does not establish that the entire brand is unindexed. The public crawl found healthy technical indexing foundations and a missing spaced-name explanation across every sitemap page. This patch addresses those signals and a measured font bottleneck. It does not establish a Google ranking improvement.

## Verified findings

| Priority | Finding | Evidence and implication |
|---|---|---|
| High | The expected brand domain does not resolve | Both `specwithcode.com` and `www.specwithcode.com` failed DNS lookup; `dig` returned NXDOMAIN. This is a discoverability and navigation gap. DNS failure alone does not establish who owns the domain or whether it is available to buy. |
| High | The spaced brand is absent | None of the 135 live sitemap pages contains the literal phrase `spec with code`. The product title says SpecWithCode, while the root site is named SpecWeave. A weak association between these names is a plausible contributor to generic results, not a proven ranking cause. |
| High | Mobile rendering has room to improve | Supermetrics PageSpeed mobile checks: home performance 75, product 70, download 83. Product lab LCP is 5.2 seconds. Render-blocking requests show about 1,250 ms potential savings. Scores are lab measurements, not real-user Core Web Vitals or ranking proof. |
| Medium | Website release facts lag behind the installer | Live schema and download copy say 1.0.62 and 156 MB. GitHub Latest was v1.0.71, with a 159,784,442-byte DMG. The download uses a Latest URL, so the installer and displayed facts differed. |

## Why the screenshot can happen

`spec with code` has ambiguous intent. It can describe keeping a specification next to implementation, specification-driven development or the SpecWithCode app. The screenshot favors established explanatory content. The canonical product lives under a different brand's domain, and its previously visible text used only the joined name. Those facts support strengthening entity identity and useful category content before treating this as a robots failure.

A live search sample for `"SpecWithCode"` returned the product page, pricing, several tutorials, documentation and the Chrome extension. A sample for `"spec with code"` produced generic material rather than an obvious product result. These are observations from the available web search tool, not a reproducible localized Google rank tracker. No position, search volume, keyword difficulty, backlink count or zero-impression claim is inferred from them.

Google supports one site name per domain or subdomain, **not a distinct site name for `/code/`**. The patch therefore retains SpecWeave as the WebSite and describes SpecWithCode as its product. Renaming the entire site or adding a fictitious second WebSite would conflate the products. [Google's site-name guidance](https://developers.google.com/search/docs/appearance/site-names).

FAQPage is retained as a semantic description matching visible content. Google retired FAQ rich results in May 2026. It is not a traffic promise. `llms.txt` was updated for name consistency, but Google explicitly says it does not affect Search visibility or rankings. [Google's current updates](https://developers.google.com/search/updates).

SoftwareApplication markup is present, but Google requires a genuine rating or review for its software-app rich result. No rating, review or aggregate was fabricated. [Google's software-app requirements](https://developers.google.com/search/docs/appearance/structured-data/software-app).

## Keyword strategy

| Query group | Intent and preferred destination | Work and measurement |
|---|---|---|
| `SpecWithCode`, `spec with code` | Find the app. Product page `/code/`. | One canonical identity, visible pronunciation, product alias, brand FAQ. Measure impressions/clicks and destination URL separately for joined/spaced searches. |
| `SpecWithCode download`, `SpecWithCode Mac` | Install. `/code/download/`. | Keep platform, signature and download facts accurate. Measure organic entrances followed by download clicks. |
| `spec-driven development` | Learn or compare methods and tools. Existing `/docs/compare/spec-driven-development-tools/`. | Category-led comparison title and link to definitions. Expand with tested examples rather than a second generic landing page. |
| `spec as code` | Understand versioned requirements. New `/docs/compare/spec-as-code/`. | Concrete example, explain limits and connect to existing workflow. Measure new-page indexing, query coverage and assisted product visits. |
| `AI coding agent` | Broad category research, often seeking an individual agent. Product plus provider tutorials. | Position the app accurately as a workspace for agents. Prefer specific queries such as `Claude Code Codex workspace` over promising to win a broad category immediately. |

This preserves the existing product decision: SpecWeave's method is **intent-first development**. Spec-driven development appears in comparison content; it is not silently reinstated as the official method name.

## Prioritized next actions

1. **After the reviewed patch deploys:** read back the product/download metadata, font requests and the new sitemap entry from the public site. Keep deployment proof separate from local build proof.
2. **Search Console owner, first session:** open the `spec-weave.com` domain property. Inspect `/code/`, `/code/download/` and `/docs/compare/spec-as-code/`; record index status, crawl time, Google-selected canonical and referring sitemap. Check Manual actions and Security issues. Submit the sitemap only if missing or failed, and record the response. Request indexing for the changed priority pages after they are live; repeated requests do not force ranking.
3. **Measurement, first week:** export the previous 90 days split by query/page, then compare finalized 28-day windows with matching country/device filters. Separate exact brand, spaced brand and nonbrand queries. Report clicks and impressions; do not average row CTR or positions. Search Console can omit anonymized low-volume queries.
4. **Conversion measurement:** existing download links have `data-track=download_click`, but an attribute alone does not prove an event is collected. Verify the existing analytics event path and organic attribution before claiming downloads or revenue. Avoid adding tracking without reviewing the site's privacy behavior.
5. **Performance:** deploy same-origin fonts, then rerun the same mobile PageSpeed URLs. Target LCP under 2.5 seconds and CLS at most 0.1; the download baseline CLS is 0.103. Audit remaining JavaScript, image sizing and edge cache lifetimes if results remain slow. Lab improvement does not establish field Core Web Vitals; the current PageSpeed response had no field data.
6. **Brand domain decision:** confirm ownership of `specwithcode.com`. If owned, configure DNS, TLS and a permanent redirect to the existing canonical product page. If not owned, assess acquisition separately. Do not launch a duplicate site or canonical migration without a measured migration plan.
7. **Authority and content, next month:** use existing GitHub README/homepage, the Chrome extension listing and original product tutorials as consistent references to the canonical product. Their current existence is verified; backlink quantity/quality is not. Add original walkthroughs showing provider handoff and concrete task evidence, and earn relevant editorial links rather than buying bulk links or manufacturing reviews.
8. **Editorial maintenance:** shorten the remaining high-intent descriptions from the saved 39-page inventory. Automate release-fact updates alongside app releases to avoid another Latest/download mismatch. Review competitor claims against primary documentation before updating the comparison matrix.
