# Lesson 11.3: TDD with SpecWeave

**Duration**: 45 minutes | **Difficulty**: Intermediate

---

## Learning Objectives

By the end of this lesson, you will be able to:
- Use SpecWeave's TDD commands and workflow
- Embed tests in tasks.md for traceability
- Leverage AI assistance in TDD cycles
- Track test coverage per acceptance criteria

## SpecWeave TDD Philosophy

SpecWeave treats tests as **first-class citizens**:

```
Traditional:   Spec → Code → Tests (afterthought)
SpecWeave:     Spec → Tests → Code (test-first)
```

Tests are embedded directly in `tasks.md`, linked to acceptance criteria.

---

## TDD Commands Overview

| Command | Purpose |
|---------|---------|
| `/specweave:tdd-cycle` | Full red-green-refactor workflow |
| `/specweave:tdd-red` | Generate failing tests |
| `/specweave:tdd-green` | Implement to pass tests |
| `/specweave:tdd-refactor` | Improve with test safety |
| `/specweave:check-tests` | Validate coverage |

describe('User Registration', () => {

      .toThrow('Password must be at least 8 characters');
  });

## Full TDD Cycle with SpecWeave

### Step 1: Start TDD Mode

```bash
/specweave:tdd-cycle
```

SpecWeave will:
1. Read your spec.md for acceptance criteria
2. Identify testable behaviors
3. Generate initial failing tests

### Step 2: Red Phase

```bash
/specweave:tdd-red
```

The AI generates comprehensive failing tests:

```typescript
// Generated by SpecWeave TDD
// AC-US1-01: Users can register with email and password

describe('Registration API', () => {
  describe('POST /api/register', () => {
    it('should create user with valid data', async () => {
      const response = await request(app)
        .post('/api/register')
        .send({
          email: 'new@example.com',
          password: 'SecurePass123!'
        });

      expect(response.status).toBe(201);
      expect(response.body).toHaveProperty('id');
      expect(response.body.email).toBe('new@example.com');
    });

    it('should hash password before storing', async () => {
      await request(app)
        .post('/api/register')
        .send({
          email: 'test@example.com',
          password: 'SecurePass123!'
        });

      const user = await db.users.findByEmail('test@example.com');
      expect(user.password).not.toBe('SecurePass123!');
      expect(user.password).toMatch(/^\$2[aby]\$.+/); // bcrypt
    });

    it('should return 400 for invalid email', async () => {
      const response = await request(app)
        .post('/api/register')
        .send({
          email: 'not-an-email',
          password: 'SecurePass123!'
        });

      expect(response.status).toBe(400);
      expect(response.body.errors).toContainEqual(
        expect.objectContaining({ field: 'email' })
      );
    });
  });
});
```

Run tests to see them fail:

```bash
npm test
# All tests fail (RED) ✓
```

### Step 3: Green Phase

```bash
/specweave:tdd-green
```

The AI implements minimal code to pass tests:

```typescript
// Minimal implementation to pass tests
import bcrypt from 'bcrypt';
import { z } from 'zod';

const RegisterSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8)
});

export async function register(data: unknown) {
  const validated = RegisterSchema.parse(data);

  const existingUser = await db.users.findByEmail(validated.email);
  if (existingUser) {
    throw new Error('Email already registered');
  }

  const hashedPassword = await bcrypt.hash(validated.password, 12);

  const user = await db.users.create({
    email: validated.email,
    password: hashedPassword
  });

  return { id: user.id, email: user.email };
}
```

Run tests to see them pass:

```bash
npm test
# All tests pass (GREEN) ✓
```

### Step 4: Refactor Phase

```bash
/specweave:tdd-refactor
```

With tests as safety net, improve the code:

```typescript
// Refactored: Better error handling, extracted validation
import bcrypt from 'bcrypt';
import { UserSchema, type CreateUserInput } from './schemas';
import { UserRepository } from './repositories';
import { DuplicateEmailError, ValidationError } from './errors';

export class RegistrationService {
  constructor(
    private users: UserRepository,
    private hashRounds = 12
  ) {}

  async register(input: CreateUserInput) {
    const validated = this.validate(input);
    await this.ensureEmailAvailable(validated.email);
    return this.createUser(validated);
  }

  private validate(input: CreateUserInput) {
    const result = UserSchema.safeParse(input);
    if (!result.success) {
      throw new ValidationError(result.error);
    }
    return result.data;
  }

  private async ensureEmailAvailable(email: string) {
    const existing = await this.users.findByEmail(email);
    if (existing) {
      throw new DuplicateEmailError(email);
    }
  }

  private async createUser(data: CreateUserInput) {
    const hashedPassword = await bcrypt.hash(data.password, this.hashRounds);
    const user = await this.users.create({
      email: data.email,
      password: hashedPassword
    });
    return { id: user.id, email: user.email };
  }
}
```

Run tests to ensure nothing broke:

```bash
npm test
# All tests still pass (REFACTOR complete) ✓
```

## tasks.md Test Format

Tests embedded in tasks follow this structure:

```markdown
### T-003: Implement password reset
**User Story**: US-002
**Satisfies ACs**: AC-US2-01, AC-US2-02, AC-US2-03
**Status**: [ ] pending

#### Implementation Notes
- Use crypto.randomBytes for token generation
- Token expires after 1 hour
- Hash token before storing

#### Tests
```typescript
describe('Password Reset', () => {
  // AC-US2-01: Request reset
  describe('requesting reset', () => {
    it('should send email for valid user', async () => {
      const spy = vi.spyOn(emailService, 'send');
      await passwordReset.request('user@example.com');
      expect(spy).toHaveBeenCalledWith(
        expect.objectContaining({
          to: 'user@example.com',
          template: 'password-reset'
        })
      );
    });

    it('should not reveal if email exists', async () => {
      // Same response for existing and non-existing
      const r1 = await passwordReset.request('exists@example.com');
      const r2 = await passwordReset.request('notexists@example.com');
      expect(r1.message).toBe(r2.message);
    });
  });

  // AC-US2-02: Token validation
  describe('validating token', () => {
    it('should accept valid token', async () => {
      const token = await createResetToken('user@example.com');
      const result = await passwordReset.validate(token);
      expect(result.valid).toBe(true);
    });

    it('should reject expired token', async () => {
      const token = await createExpiredToken('user@example.com');
      const result = await passwordReset.validate(token);
      expect(result.valid).toBe(false);
      expect(result.reason).toBe('Token expired');
    });
  });

  // AC-US2-03: Setting new password
  describe('setting new password', () => {
    it('should update password with valid token', async () => {
      const token = await createResetToken('user@example.com');
      await passwordReset.complete(token, 'NewSecure123!');

      const user = await db.users.findByEmail('user@example.com');
      const isValid = await bcrypt.compare('NewSecure123!', user.password);
      expect(isValid).toBe(true);
    });

    it('should invalidate token after use', async () => {
      const token = await createResetToken('user@example.com');
      await passwordReset.complete(token, 'NewSecure123!');

      const result = await passwordReset.validate(token);
      expect(result.valid).toBe(false);
    });
  });
});
`` `
```

## TDD Quality Gates

SpecWeave validates TDD compliance before closing increments:

```bash
/specweave:done 0001
```

```
PM Validation: TDD Quality Gate
================================

✓ All tasks have embedded tests
✓ All ACs have test coverage
✓ Tests are passing (47/47)
✓ Coverage threshold met (87% > 80%)

Increment ready to close.
```

If tests are missing:

```
PM Validation: TDD Quality Gate
================================

✗ Missing tests for AC-US1-04
✗ Task T-005 has no embedded tests
✗ Coverage below threshold (72% < 80%)

Cannot close increment. Run /specweave:tdd-red to add missing tests.
```

## AI-Assisted Test Generation

SpecWeave's AI generates tests based on:

1. **Acceptance Criteria** — From spec.md
2. **Type Definitions** — Infers expected behavior
3. **Similar Code** — Learns from existing tests
4. **Edge Cases** — Common patterns for your domain

Example prompt that SpecWeave uses:

```
Generate failing tests for AC-US3-01:
"Users can filter products by category"

Context:
- ProductService.filterByCategory(category: string): Product[]
- Categories: 'electronics', 'clothing', 'books'
- Products have: id, name, price, category

Generate tests for:
1. Happy path
2. Empty results
3. Invalid category
4. Case sensitivity
```

## Best Practices

### 1. Write Tests Before Implementation

Don't cheat! Write failing tests first:

```bash
# Correct flow
/specweave:tdd-red    # Tests fail
npm test              # Verify RED
/specweave:tdd-green  # Implement
npm test              # Verify GREEN
```

### 2. Link Tests to ACs

Always reference which AC a test covers:

```typescript
// AC-US1-01: Email validation
it('should reject invalid email', () => { ... });
```

### 3. Keep Tests in tasks.md

Tests belong with their tasks for traceability:

```markdown
### T-001: Feature implementation
**Satisfies ACs**: AC-US1-01

#### Tests
(embedded tests here)
```

### 4. Use Coverage Targets

Set minimum coverage per increment:

```yaml
# In increment metadata.json
{
  "quality_gates": {
    "test_coverage_minimum": 80
  }
}
```

1. **Tests are first-class** — Embedded in tasks.md, linked to ACs
