# SpecWeave Switch

A local companion for selecting native coding subscriptions and restoring reviewed Git work. SpecWeave remains the durable project/intent/task record; this companion holds account observations and managed execution receipts. No native conversation is transcoded and no OAuth credentials are copied between providers.

Requires Node 22. Run `python3 scripts/install-switch.py --node /absolute/path/to/node22 --service` from this directory to install a versioned private bundle, an absolute Node launcher and the loopback launchd service. The installer preserves existing launchers/services for explicit update review. `specweave-switch init` preserves current native stores and prepares four Codex and three Claude profile slots. `specweave-switch refresh` checks native authentication and Codex rate-limit observations. Unsigned profiles require each account's own native login. Unavailable Claude quota stays unknown; a successful sign-in is not inference proof.

The private dashboard runs at `http://127.0.0.1:8318` with `specweave-switch serve`. Balanced favors the least-used eligible account. Reset-first favors the account whose observed reset occurs soonest. Spend-first favors the most-used eligible account, consuming its remaining allowance before switching. Existing runs keep their selected account. Unknown or expired quota requires explicit selection with `--allow-unknown`. Account selection applies to the next managed run; it does not change any already-running Codex, Claude, or T3 thread.

Use `specweave-switch --help` for run/checkpoint/restore options. Read-only is the run default. `--sandbox workspace-write` explicitly enables native Codex workspace edits or Claude file tools under standard edit permissions; Claude shell and protected writes still require native approval. Exclusive leases apply to this companion's managed runs. Check external native sessions and SpecWeave task ownership before authorizing writes. Automatic failover is read-only and starts a new bounded attempt only after the previous child exits. Native authentication errors and ordinary task failures preserve failed receipts.

Checkpoint files are host-local and private. Capture requires explicit tracked file paths; secret paths/content, symlinks and arbitrary untracked files are denied. Restoration uses a verified base and a new isolated Git worktree. The prior checkout stays intact. A partial restoration is preserved for inspection. Checkpoints carry code state, not hidden reasoning, attachments, pending provider approvals or every tool transcript.

CLIProxyAPI 8.0.17 is separately installed as `specweave-cliproxy`, using `~/.local/share/specweave/proxy`, loopback port 8317, separate protected client/management keys and bounded affinity/retry settings. It initially has no signed-in upstream provider; a 200 model-list response with zero models is startup/authentication proof only. Keep Claude subscription login in its unmodified native CLI. Do not configure API-paid fallback merely to consume subscriptions. VibeProxy is installed as a separate Mac application and remains inactive while this proxy owns 8317.

T3 stable 0.0.45 and the isolated nightly 0.0.46-nightly.20261007.2761 are separate. `scripts/install-local.py` installs the digest-pinned nightly CLI; `t3-nightly serve --host 127.0.0.1 --port 3774 --base-dir ~/.local/share/specweave/t3-nightly/runtime --no-browser` evaluates it without replacing stable state. Nightly's orchestrator requires its beta mobile client; App Store/Google Play stable clients cannot connect to it. Source/release presence is separate from orchestration and account-transfer acceptance tests.

Tailscale installation is separate from macOS network-extension consent, native sign-in and verified tailnet access. Workers need exact verified host keys and authenticated Remote Login. Run `scripts/worker-bootstrap.sh m1` or `m3` only on the intended authenticated worker. It preserves native stores and installs providers in an isolated prefix. Existing companion destinations stop the script before replacement. Confirm actual host identity, versions, native sign-in, sandbox inference and pairing before accepting work on a worker. Never synchronize live SQLite databases or share a writable checkout between Macs.

All automated browser checks explicitly run headless, with `PWDEBUG=0` and `PLAYWRIGHT_HTML_OPEN=never`. Screenshots are saved as files. No provider token or machine password belongs in source, checkpoint, screenshots or reports.

The main Mac's `specweave-mac` helper uses the dedicated private SSH key and verified pins from `~/.local/share/specweave/fleet`, with host references in its private `hosts.json`. `specweave-mac m3 status` reads the worker's own observations. `specweave-mac m1 run --cwd /absolute/worker/git/path --account codex-1 --prompt 'Read the project brief'` runs under that worker's native identity and sandbox. `specweave-mac m3 dashboard` opens a foreground loopback SSH tunnel on port 28318 (M1 uses 18318); keep that command running while viewing the worker dashboard. The helper does not move a project or live session between hosts. Source changes still require a reviewed portable handoff and each worker's own checkout.
