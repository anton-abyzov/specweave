# Self-Improving Skills (Reflect)

## Overview

The Reflect system enables **continual learning across sessions**. Instead of starting from zero every conversation, Claude learns from corrections, successful patterns, and user preferences - persisting knowledge in skill memory files.

```
Session 1: User corrects button style → Reflect captures learning
Session 2: Claude uses correct button style without being reminded
Session 3+: Knowledge compounds, Claude gets smarter over time
```

---

## The Problem

Every LLM session starts from zero:

1. **Monday**: You correct Claude - "Use our primary button component, not a custom style"
2. **Tuesday**: Claude makes the same mistake again
3. **Wednesday**: Same correction, same frustration
4. **Forever**: Without memory, you're repeating yourself indefinitely

This manifests as:
- Wrong naming conventions
- Incorrect logging patterns
- Missing input validation
- Wrong component usage
- Forgotten architectural decisions

---

## The Solution

Reflect analyzes sessions and persists learnings in **centralized memory files** - no skill copying needed!

```
# CENTRALIZED ARCHITECTURE (v1.0.93+)
# Users DON'T need copies of skills - just the memory folder

~/.specweave/memory/           # Global memory (across all projects)
├── component-usage.md         # All UI component learnings
├── api-patterns.md            # All API pattern learnings
├── testing.md                 # All testing learnings
├── deployment.md              # Wrangler, Vercel, Supabase patterns
├── security.md                # Auth, validation learnings
├── database.md                # Query, schema learnings
└── general.md                 # Miscellaneous patterns

.specweave/memory/             # Project-specific memory
├── component-usage.md         # This project's UI patterns
├── api-patterns.md            # This project's API patterns
└── architecture.md            # This project's design decisions
```

**Key benefit**: No need to copy skills into each project! Memory is centralized by category, and plugin skills (from marketplace) automatically benefit from learned patterns.

## How It Works

### 1. Signal Detection

Reflect identifies two types of signals in conversation:

**Corrections (High Confidence)**
```
User: "No, don't use that button. Use our <Button variant='primary'> component."
      → LEARNING: Always use Button component with variant='primary'
      → CATEGORY: component-usage
      → CONFIDENCE: high
```

**Approvals (Medium Confidence)**
```
User: "Perfect! That's exactly how our API patterns should look."
      → LEARNING: Continue using this API pattern structure
      → CATEGORY: api-design
      → CONFIDENCE: medium
```

### 2. Learning Extraction

Each learning is structured:

```json
{
  "id": "LRN-2026-01-05-001",
  "timestamp": "2026-01-05T10:30:00Z",
  "type": "correction",
  "confidence": "high",
  "category": "component-usage",
  "context": "User corrected button component usage in settings page",
  "learning": "Always use <Button variant='primary'> from @/components/ui/button for primary actions. Never create custom button styles.",
  "triggers": ["button", "primary", "action", "component"],
  "skill": "frontend",
  "source": "session:auto-2026-01-05-abc123"
}
```

### 3. Memory Persistence

Learnings are written to **centralized category files**:

```markdown
# .specweave/memory/component-usage.md

# Component Usage Memory

> Auto-generated by SpecWeave Reflect. Edit with caution.
> Last updated: 2026-01-05T10:30:00Z
> Location: Centralized in .specweave/memory/

## Learned Patterns

#### LRN-2026-01-05-001 (High Confidence)
**Context**: User corrected button component usage in settings page
**Learning**: Always use `<Button variant='primary'>` from `@/components/ui/button` for primary actions. Never create custom button styles.
**Triggers**: button, primary, action, component
**Added**: 2026-01-05
**Source**: session:auto-2026-01-05

#### LRN-2026-01-04-003 (High Confidence)
**Context**: Correction on component file naming
**Learning**: Use PascalCase for component files: `UserProfile.tsx` not `user-profile.tsx`
**Triggers**: component, naming, file, tsx
**Added**: 2026-01-04
**Source**: session:manual-2026-01-04
```

### 4. Context Loading (Centralized Memory Integration)

**The key insight**: Plugin skills don't need modification! Centralized memory is loaded via:

1. **CLAUDE.md includes memory loading instruction** (added by SpecWeave)
2. **SessionStart hook** can inject relevant memory context
3. **Skills reference centralized memory** via standard patterns

```
User: "Create a button for the settings page"
      ↓
Claude: Session starts
      ↓
CLAUDE.md instruction: "Check .specweave/memory/ for learned patterns"
      ↓
Claude: Reads .specweave/memory/component-usage.md (if exists)
      ↓
Learned patterns loaded into context
      ↓
Claude: "I'll use <Button variant='primary'> from our design system..."
      (Applied learned pattern without skill modification!)
```

**No skill copying required** - memory is injected at session level, not skill level.

## Usage

### Manual Reflection

After completing work, manually trigger reflection:

```bash
# Reflect on current session
/sw:reflect

# Reflect on specific skill
/sw:reflect --skill frontend

# Reflect with custom prompt
/sw:reflect "Focus on the database query patterns we discussed"
```

### Automatic Reflection

Enable auto-reflection on session end:

```bash
# Enable automatic reflection (via stop hook)
/sw:reflect-on

# Disable automatic reflection
/sw:reflect-off

# Check reflection status
/sw:reflect-status
```

When enabled, the stop hook automatically:
1. Analyzes the session transcript
2. Extracts corrections and approvals
3. Updates relevant skill MEMORY.md files
4. Commits changes to git (if configured)

## Configuration

### Global Settings

In `~/.claude/settings.json`:

```json
{
  "reflect": {
    "enabled": true,
    "autoReflect": false,
    "confidenceThreshold": "medium",
    "maxLearningsPerSession": 10,
    "retentionDays": 90,
    "gitCommit": true,
    "gitPush": false
  }
}
```

### Project Settings

In `.specweave/config.json`:

```json
{
  "reflect": {
    "enabled": true,
    "autoReflect": true,
    "skillsPath": ".specweave/skills",
    "categories": [
      "component-usage",
      "api-patterns",
      "testing",
      "deployment",
      "security",
      "database"
    ]
  }
}
```

|-------|------------|---------|--------|

## Integration with Auto Mode

When `/sw:auto` runs with reflection enabled:

```
1. Start auto session
      ↓
2. Claude executes tasks
      ↓
3. User makes corrections (if any)
      ↓
4. Session completes (all tasks done)
      ↓
5. Stop hook triggers
      ↓
6. Reflect analyzes transcript
      ↓
7. Learnings extracted and saved
      ↓
8. Git commit (if configured)
      ↓

```

## Best Practices

### For Corrections

**Good corrections (high signal)**:
```
"Never use that approach. Always use X because..."
"Don't create custom components. We have a design system..."
"Wrong pattern. The correct way is..."
```

**Weak corrections (low signal)**:
```
"Hmm, maybe try something else?"
"That doesn't look quite right"
```

### For Approvals

**Strong approval (captured)**:
```
"Perfect! That's exactly how we do it."
"This is the right pattern, well done."
"Yes, always follow this approach."
```

**Neutral (not captured)**:
```
"OK"
"Sure"
"Proceed"
```

### Memory Organization (Centralized)

1. **Global memory** (`~/.specweave/memory/`) for patterns across all projects
2. **Project memory** (`.specweave/memory/`) for project-specific patterns
3. **Team memory** (shared repo `.specweave/memory/`) for team-wide conventions

**No skill copying required!** Plugin skills from marketplace work automatically with centralized memory.

---

## Privacy & Security

- Memory files contain only **patterns and learnings**, not raw conversation
- No sensitive data (credentials, keys) is ever stored
- Memory files can be gitignored if needed
- Clear command available: `/sw:reflect-clear`

## Troubleshooting

### Learnings Not Persisting

1. Check reflection is enabled: `/sw:reflect-status`
2. Verify skills directory exists
3. Check file permissions
4. Review logs: `.specweave/logs/reflect/`

### Wrong Learnings Applied

1. View memory file: `cat ~/.claude/skills/frontend/MEMORY.md`
2. Remove specific learning manually or via git rollback
3. Use `/sw:reflect-clear --learning LRN-XXX` to remove

### Too Many Learnings

Configure max learnings per session:
```json
{
  "reflect": {
    "maxLearningsPerSession": 5,
    "confidenceThreshold": "high"
  }
}
```
